1. 개요

Ability 게임에서 자기장이 최종적으로 모이는 위치를 매 게임마다 랜덤하게 결정한다. 중심은 게임 시작 시 단 한 번 결정되며, 게임 내내 모든 자기장 단계(초기, 1차, 2차, 3차)가 동일한 중심으로 줄어든다.

구현은 game-core / world-border-custom-center 기능을 사용한다. 즉, GameMap.currentWorldBorderCenterLocation을 게임 시작 시 한 번 세팅하는 것이 본 기능의 본체이다.

2. 문제 정의

  • 현재는 자기장이 항상 맵 원본 중심으로 수렴하여, 매 게임 마지막 교전 위치가 동일하다.
  • 플레이어 입장에서 자기장이 줄어드는 위치를 미리 알 수 있어 후반부 전략이 단조로워진다.
  • 같은 맵을 반복 플레이할 때 신선함이 떨어진다.

3. 정책 정의

3.1 핵심 규칙

  1. 자기장 중심은 게임 시작 시 1회만 랜덤으로 결정한다.
  2. 일단 결정되면 게임이 끝날 때까지 절대 변경되지 않는다(월드보더 정사각형 제약).
  3. 결정된 중심은 모든 자기장 단계(초기, 1차, 2차, 3차)에 동일하게 적용된다.

3.2 중심 가능 범위

자기장 중심은 맵의 가운데 1/3 영역 안에서 랜덤으로 뽑는다. 즉, 맵의 가장자리에서 맵 한 변의 1/3 이상 떨어진 위치여야 한다.

예시: 한 변 300 짜리 맵 (맵 영역 0 ~ 300)

  • 맵 가운데 1/3 영역: 100 ~ 200
  • 자기장 중심 x ∈ [100, 200], z ∈ [100, 200]

예시: 한 변 600 짜리 맵 (맵 영역 0 ~ 600)

  • 맵 가운데 1/3 영역: 200 ~ 400
  • 자기장 중심 x ∈ [200, 400], z ∈ [200, 400]

3.3 수식

맵 원본 중심을 (cx, cz), 맵 한 변 길이를 M = worldBorderSize라 할 때:

offset_max = M / 6

그리고 새 중심 (nx, nz)는 다음 범위에서 균등 분포로 샘플링한다:

nx ∈ [cx - offset_max, cx + offset_max]
nz ∈ [cz - offset_max, cz + offset_max]

이렇게 하면 nx가 가장자리(cx ± M/6)에 위치할 때, 그 점에서 맵 가장자리까지의 거리가 M/2 - M/6 = M/3이 된다. 즉, 자기장 중심에서 맵 가장자리까지 항상 최소 M/3의 여유가 보장된다.

3.4 자기장 단계 크기

자기장 크기 단계는 현재 정의된 그대로 유지한다. (worldBorderSize가 자기장이 맵 안에 들어가도록 적절히 설정되어 있다는 전제)

단계 크기 대기 시간 키 축소 속도 키
초기 worldBorderSize (한 변) - -
1차 worldBorderSize × 2/3 firstWorldBorderReduceWaitSeconds firstWorldBorderReduceSizePerSeconds
2차 worldBorderSize × 1/3 secondWorldBorderReduceWaitSeconds secondWorldBorderReduceSizePerSeconds
3차 20 (고정) thirdWorldBorderReduceWaitSeconds thirdWorldBorderReduceSizePerSeconds

4. 범위

포함

  • AbilityWorldBorderCenterListener가 게임 시작 시 자기장 중심을 1회 랜덤 결정한다.
  • 결정된 중심을 GameCore.currentMap.currentWorldBorderCenterLocation에 세팅한다.
  • ability-game-config.yml의 경계선 랜덤 설정으로 기능을 켜고 끌 수 있다.
  • 중심 가능 범위(맵의 가운데 1/3)는 코드 상수로 하드코딩한다(기존 자기장 비율과 동일한 방식).

제외

  • 중심 가능 범위 비율을 설정으로 빼지 않는다.
  • 중심 좌표 후보 리스트, 지형 적합성 검사 등 고급 정책은 본 범위에 포함하지 않는다.
  • 자기장 단계 크기/속도/대기 시간 자체는 변경하지 않는다.

5. 기능 요구사항

ID 요구사항 상세
FR-1 1회 결정 자기장 중심은 게임 시작 시 단 한 번만 결정되어야 한다. 게임 중 재계산은 금지한다.
FR-2 샘플링 범위 중심은 맵 원본 중심에서 체비쇼프 거리 worldBorderSize / 6 이내에서 균등 분포로 샘플링한다.
FR-3 세팅 시점 1차 자기장 단계(WorldBorderUpdatePhase)가 시작되기 전에 세팅이 완료되어야 한다. 구현 방식은 GameStartedEvent 리스너에서 처리한다.
FR-4 좌표 적용 결정된 중심을 GameCore.currentMap.currentWorldBorderCenterLocation에 세팅한다.
FR-5 월드 일치 새 중심의 world는 맵 원본 중심의 world와 동일해야 한다.
FR-6 y / yaw / pitch 처리 x, z만 랜덤화하고 y, yaw, pitch는 맵 원본 중심 값을 그대로 복사한다.
FR-7 비활성 호환 맵 또는 중심이 null인 경우 본 기능을 스킵해도 게임이 정상 진행되어야 한다(기존 동작 = 맵 원본 중심 사용).
FR-8 설정 토글 ability-game-config.yml의 경계선 랜덤이 false면 랜덤 중심을 적용하지 않고 기존 맵 원본 중심을 사용한다. 기본값은 true다.

6. 기술 설계

구현 위치

본 기능은 GameStartedEvent를 구독하는 Listener로 구현한다. 파이프라인(AbilityPhasePipeline)은 수정하지 않는다. GameRecordListener 등 기존 GameStartedEvent 사용처와 동일한 패턴을 따른다.

중심 계산 및 적용 로직

// ability-core 측 리스너 (예: AbilityWorldBorderCenterListener)
class AbilityWorldBorderCenterListener : Listener {

    @EventHandler
    fun onGameStarted(event: GameStartedEvent) {
        if (!AbilityApi.abilityGameConfig.useRandomWorldBorderCenter) return

        val map = GameCore.currentMap ?: return
        val center = map.centerLocation ?: return

        val maxOffset = map.worldBorderSize / 6
        val offsetX = Random.nextInt(-maxOffset, maxOffset + 1)
        val offsetZ = Random.nextInt(-maxOffset, maxOffset + 1)

        val newCenter = Location(
            center.world,
            center.x + offsetX,
            center.y,
            center.z + offsetZ,
            center.yaw,
            center.pitch,
        )

        map.currentWorldBorderCenterLocation = newCenter
    }
}

GameStartedEvent는 플레이어가 맵에 텔레포트 되기 전에 발행된다(GameStartedEvent.kt 주석 참조). 또한 1차 WorldBorderUpdatePhase는 StartCountPhase, AbilityDrawPhase, GodModePhase를 거친 뒤에야 시작되므로, 이 리스너에서 동기적으로 currentWorldBorderCenterLocation을 세팅하는 것만으로 모든 자기장 단계가 새 중심을 사용하게 된다.

리스너 등록

ability-core의 플러그인 초기화 코드에서 다른 리스너들과 동일하게 등록한다. 특별한 의존성 주입 없이 PluginManager.registerEvents로 충분하다.

샘플링 동작 검증

맵 한 변 maxOffset 중심 가능 영역 최대 자기장(초기) 맵 침범 여부
300 50 한 변 100 (가장자리에서 최소 100) 적절히 작은 맵을 사용하는 한, 운영 측 책임
600 100 한 변 200 (가장자리에서 최소 200) 동일
1200 200 한 변 400 (가장자리에서 최소 400) 동일

본 정책은 "맵 가운데 1/3 영역만 사용"한다. 즉, 자기장 중심에서 맵 가장자리까지 항상 worldBorderSize / 3의 여유가 있다는 것이지, "자기장이 맵 안에 들어간다"는 강한 보장은 아니다. 초기 자기장 크기가 worldBorderSize 그 자체이기 때문에, 중심을 옮긴 만큼 자기장은 반대편으로 삐져나간다. 이 트레이드오프는 운영 측에서 worldBorderSize를 실제 사용 가능한 맵 영역보다 충분히 작게 설정함으로써 흡수해야 한다.

7. 통합 방식

파이프라인 변경 없음

본 기능은 AbilityPhasePipeline을 수정하지 않는다. 파이프라인 구조와 페이즈 순서는 그대로 두고, 별도 Listener가 GameStartedEvent를 받아 currentWorldBorderCenterLocation을 세팅한다. 이후 WorldBorderUpdatePhase들은 game-core 기능에 의해 자동으로 새 중심을 사용한다.

[GameManager] StartCountPhase 진행 ... -> StartCountPhase 내부에서 GameCore.unsafe.gameManager.onGameStarted() 호출 -> GameStartedEvent 발행 -> [ability-core] AbilityWorldBorderCenterListener.onGameStarted -> map.currentWorldBorderCenterLocation = (랜덤 중심) 세팅 이후 페이즈 진행 -> AbilityDrawPhase -> GodModePhase -> WorldBorderUpdatePhase 1차 (자동으로 새 중심 사용) -> WorldBorderUpdatePhase 2차 (자동으로 새 중심 사용) -> WorldBorderUpdatePhase 3차 (자동으로 새 중심 사용) -> ...

이벤트 리스너 방식 선택 근거

  • 책임 분리: 자기장 중심 결정은 게임 모드의 부가 정책이며, 파이프라인 구조에 끼워 넣지 않아도 된다.
  • 일관된 패턴: game-replay, game-history 등 다른 모듈도 GameStartedEvent를 구독하는 Listener 방식으로 게임 시작 시 초기화를 수행한다.
  • 시점 보장: GameStartedEvent는 플레이어 텔레포트 이전에 발행되고, 1차 자기장 단계는 그 이후 여러 페이즈를 거쳐서야 시작되므로 세팅 누락 위험이 없다.
  • 파이프라인 가독성 유지: AbilityPhasePipeline에 자기장 중심 결정 같은 부가 로직을 추가하지 않아 파이프라인이 본질만 표현한다.

8. 리스크 및 검증 계획

맵 설정상 worldBorderSize가 실제 맵 영역과 같다면 자기장이 맵 밖으로 삐져나간다. 운영 측에서 맵 영역보다 worldBorderSize를 충분히 작게(예: 1/3 이상 여유) 설정해야 한다. 본 기능은 이 검증을 코드로 강제하지 않는다.

랜덤 중심이 절벽, 용암, 물 한복판 등 게임 진행이 어려운 위치에 떨어질 수 있다. 본 기능은 지형 적합성을 고려하지 않는다. 너무 자주 문제가 되면 후속 작업에서 "후보 좌표 리스트" 또는 "지형 검증" 정책을 추가한다.

검증 항목

  • 게임 시작마다 자기장 중심이 매번 달라지는지(샘플링이 실제로 일어나는지) 확인한다.
  • 결정된 중심이 맵 가운데 1/3 영역 안에 있는지 확인한다(범위 밖 샘플링이 일어나지 않음).
  • 모든 자기장 단계(1차, 2차, 3차)가 동일한 중심으로 줄어드는지 확인한다.
  • 1차 자기장이 시작된 이후 중심이 절대 바뀌지 않는지(자기장 순간이동이 없는지) 확인한다.
  • WorldBorderUpdatePhase의 미리보기 파티클이 새 중심을 기준으로 그려지는지 확인한다.
  • 리플레이 녹화 후 재생 시 자기장이 녹화 시점의 중심으로 정확히 그려지는지 확인한다.
  • 게임이 정상 종료된 후 다음 게임을 시작하면, 또 다른 새 중심으로 자기장이 동작하는지 확인한다(이전 게임 중심이 누수되지 않음).
  • 여러 맵에서 동일하게 동작하는지 확인한다(특히 worldBorderSize가 다른 맵들).
